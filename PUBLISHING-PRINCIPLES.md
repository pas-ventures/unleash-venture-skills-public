# Publishing Principles

These skills are intentionally venture-agnostic. They're tools for any operator working through go-to-market — not a portfolio of work we've done.

## Rules

- **No portfolio names** anywhere — not in skill content, examples, commit messages, branch names, PR titles, comments, or tags. Skills work in any operator's hands; they're not advertisements for the work that produced them.
- **Examples are illustrative** — generic categories ("trades businesses", "professional-services firms", "service-firms with field operatives") over specific niche names.
- **CI inputs are operator-supplied** — design tokens (colors, fonts, logo, tone register) are placeholders the operator fills in. No baked-in brand assumptions.
- **Source citations are generic** — "industry-specific practitioner forums" rather than the URL of a specific forum used in our own build.

## Contributing

If you're contributing a patch and want to credit the source of an insight, do it by category ("from real-world battle-testing on a German trades niche") rather than by venture name.

This file's rules apply to: skill MD content + commit messages + branch names + PR titles + comments + tags + any other surface that ships in the repo.
